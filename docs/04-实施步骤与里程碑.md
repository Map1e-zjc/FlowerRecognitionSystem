### M2-1 实现训练框架

- `ml/models.py`：`build_model(name, num_classes=102, pretrained=True)`，支持 `resnet50 / efficientnet_b0 / convnext_tiny / vit_b16`（timm 主干）
- `ml/train.py` 必须包含：
  1. `param_groups` 分层学习率 + 前 3 epoch 冻结主干 warmup；
  2. AMP（`autocast` + `GradScaler`）；
  3. `CosineAnnealingLR` + 线性 warmup + `clip_grad_norm_(1.0)`；
  4. 每 epoch 记录 train loss / val Top-1 / val Top-5，写 CSV 日志；
  5. 早停（val Top-1 连续 10 epoch 不提升）与最佳权重保存；
  6. `--seed`、`--epochs`、`--batch-size`、`--device`、`--resume` 命令行参数；
  7. 进度条与显存/耗时打印。
- 判据：`--help` 输出所有参数说明；中断后 `--resume` 能从 checkpoint 继续

> ### 🔧 M2-1 执行中追加的两项加固（实测踩坑后补上）
>
> **加固 1 · 进度条治理（防日志刷屏）**
>
> 现象：tqdm 在**非 TTY**（后台作业 / 管道 / 日志采集）下仍逐步输出，实测
> ConvNeXt-Tiny 只跑 40 秒就产生 **157.8 KB** 控制台日志，60 epoch 推算可达 10 MB 级，
> 会把作业输出缓冲区打爆并淹没真正有用的信息（实测触发过内存丢弃）。
>
> 修复：进度条收敛到唯一实现 `ml/utils.py::make_bar`，策略 `auto`（默认）——
> 仅当 `stderr.isatty()` 为真才显示；可用 `--progress` / `--no-progress` 或
> `ML_PROGRESS=1/0` 强制覆盖。实测对照：3 batch 的单 epoch
> **默认 3.61 KB vs `--progress` 18.97 KB**。
>
> **加固 2 · 缓存目录兜底（防 C 盘写失败）**
>
> 现象：未设 `TORCH_HOME` 时 torchvision 会尝试写 `C:\Users\<user>\.cache\torch`，
> 在受限环境下直接抛 `PermissionError: [WinError 5] 拒绝访问`，
> 报错信息完全指不到真正原因。
>
> 修复：`ml/utils.py::ensure_cache_env()` 在 `train/evaluate` 入口处兜底设置
> `PIP_CACHE_DIR / TORCH_HOME / HF_HOME / HF_ENDPOINT` 到项目内 `.cache/` 并建目录；
> 显式传入的环境变量优先级更高。这样无论用 `scripts/train.ps1` 还是直接
> `python -m ml.train` 都不会踩坑。

3. **训练与推理一致性**：预处理函数只有一份实现，训练与后端共用，避免"报告 96%、线上 70%"。
4. **每完成一个里程碑即 commit 一次**，commit message 写清里程碑编号。
5. **不做范围蔓延**：文档 01 §5.3 的可选加分项只在主线全部完成后才动。
6. **失败就记录**：调优失败的轮次也要写进报告（消融实验），不要删除。
