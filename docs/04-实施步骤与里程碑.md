## 3. M2 · 模型训练与对比（第 4—9 天）

### M2-1 实现训练框架

- `ml/models.py`：`build_model(name, num_classes=102, pretrained=True)`，支持 `resnet50 / efficientnet_b0 / convnext_tiny / vit_b16`（timm 主干）
- `ml/train.py` 必须包含：
  1. `param_groups` 分层学习率 + 前 3 epoch 冻结主干 warmup；
  2. AMP（`autocast` + `GradScaler`）；
  3. `CosineAnnealingLR` + 线性 warmup + `clip_grad_norm_(1.0)`；
  4. 每 epoch 记录 train loss / val Top-1 / val Top-5，写 CSV 日志；
  5. 早停（val Top-1 连续 10 epoch 不提升）与最佳权重保存；
  6. `--seed`、`--epochs`、`--batch-size`、`--device`、`--resume` 命令行参数；
  7. `tqdm` 进度条 + 显存/耗时打印。
- 判据：`--help` 输出所有参数说明；中断后 `--resume` 能从 checkpoint 继续

### M2-2 训练 ResNet-50（基线）

```powershell
python -m ml.train --config ml/configs/resnet50.yaml --seed 42
```

- 期望：60 epoch，约 30—40 分钟，val Top-1 ≈ 93—95%
- 判据：`checkpoints/resnet50_best.pth` + `figures/resnet50_curves.png` 产出
- ⭐ 此步完成即可**启动 M3 后端开发**（并行）

### M2-3 训练 EfficientNet-B0

```powershell
python -m ml.train --config ml/configs/efficientnet_b0.yaml --seed 42
```

- 期望：约 20—30 分钟，val Top-1 ≈ 94—96%（参数量仅 5.3 M，性价比最高）

### M2-4 训练 ConvNeXt-Tiny

```powershell
python -m ml.train --config ml/configs/convnext_tiny.yaml --seed 42
```

- 期望：约 45—60 分钟；若 OOM 则 batch 32 → 16

### M2-5 训练 ViT-B/16（冲最优指标）

```powershell
python -m ml.train --config ml/configs/vit_b16.yaml --seed 42
```

- 期望：约 70—90 分钟，val Top-1 ≈ 96—98%
- 风险应对：显存不足 → batch 16 + 梯度累积 ×2；仍不足 → 192px 输入或改用 `vit_base_patch16_224.augreg_in21k` 并降 epoch 到 40

### M2-6 测试集评估与指标导出

```powershell
python -m ml.evaluate --weights ml/outputs/checkpoints/vit_b16_best.pth --split test
python -m ml.export_metrics      # 汇总 4 个模型 → ml/outputs/metrics.json
```

- 产出：`metrics.json`（结构见文档 03 §4.2）、每个模型的 `*_confusion.png`、`compare_models.png`
- 判据：最优模型 **Top-1 ≥ 95% 且 Top-5 ≥ 99%**；若未达标，执行 M2-7 调优

### M2-7 调优回路（仅在未达标时执行，最多 3 轮）

按顺序尝试并记录每轮结果到报告（这本身就是消融实验素材）：

1. 增强升级：启用 `RandAugment(2, 9)` + `RandomErasing(0.25)`；
2. 分辨率提升：ViT-B/16 用 320/384 输入做 10 epoch 微调；
3. 学习率/epoch 调整：`lr_backbone` 3e-5 → 1e-4，epoch 60 → 100；
4. 模型集成：ResNet-50 + ViT-B/16 概率平均（推理耗时翻倍，作为可选方案）。

### M2-8 错误分析

- 产出：`figures/error_cases/`（Top-20 高置信度错分样本）、Top-10 混淆对统计表
- 判据：报告中每个混淆对都有原因假设（文档 03 §4.3）

**M2 完成标志**：4 个模型训练完毕，`metrics.json` 中 `best_model` 达标，图表与错误分析齐全。

## 4. M3 · 后端 API（第 7—12 天）

### M3-1 工程骨架与配置

- 文件：`app/main.py`（`FastAPI` + `lifespan` + CORS + 全局异常处理器）、`app/core/config.py`（`pydantic-settings` 读 `.env`）、`app/core/logging.py`
- `.env.example`：`SECRET_KEY / ACCESS_TOKEN_EXPIRE_MINUTES=720 / DATABASE_URL=sqlite:///./flowers.db / UPLOAD_DIR / DEFAULT_MODEL / MAX_UPLOAD_MB=5 / CORS_ORIGINS`
- 判据：`uvicorn app.main:app --reload --port 8000` 启动成功，`http://127.0.0.1:8000/docs` 可打开

### M3-2 数据库与种子数据

- 建表：`users / flowers / recognition_records / model_metrics`（schema 见文档 02 §5）
- 种子导入：`flowers.json`（102 条）→ `flowers` 表；`metrics.json` → `model_metrics` 表
- 判据：`init_db.py` 重复执行幂等（不重复插入）；`SELECT COUNT(*) FROM flowers` = 102

### M3-3 认证模块（FR-04）

- `POST /auth/register`（用户名/邮箱唯一性校验、密码强度校验、bcrypt 哈希）
- `POST /auth/login`（签发 JWT，12 小时有效）
- `GET /auth/me`（`Depends(get_current_user)` 依赖）
- 判据：用 `/docs` 完成注册→登录→带 token 访问 `/auth/me`；错误密码返回 401 且提示为中文

### M3-4 识别接口（FR-01，核心）

- `POST /predict`：
  1. 校验认证 → 校验文件（后缀/MIME/大小/Pillow 可解码）；
  2. EXIF 方向纠正 → RGB 转换；
  3. 存盘 `uploads/{user_id}/{uuid4().hex}.{ext}`；
  4. 调用 `services/inference.py` 的模型单例推理（`torch.no_grad()` + AMP）；
  5. `softmax` → `topk(5)` → 关联 `flowers` 表中文名；
  6. 写 `recognition_records` 记录 → 返回 Top-5 + `latency_ms`；
  7. 全局 `asyncio.Lock` 串行化 GPU 推理，避免并发导致的显存竞争（NFR-03）。
- `services/inference.py` 关键点：预处理必须与 `ml/dataset.py` 的**测试集 transform 完全一致**（文档 03 §3.3 铁律）；启动时一次性加载权重。
- 判据：
  - 上传一张测试集图片，Top-1 结果与 `ml.evaluate` 输出一致；
  - 上传 `.txt` 文件返回 4001 中文提示；
  - 上传 6 MB 图片返回 4002；
  - 纯推理 `latency_ms < 300`（GPU）

### M3-5 百科接口（FR-02）

- `GET /flowers`（keyword 模糊搜索中英文名 + 分页）、`GET /flowers/{class_id}`
- 判据：搜索"玫瑰"能命中；分页参数非法时返回 422 校验提示

### M3-6 历史记录接口（FR-03）

- `GET /history`（本人、分页、按 class_id 过滤）、`GET /history/{id}`、`DELETE /history/{id}`
- 判据：用户 A 无法访问用户 B 的记录（返回 404）

### M3-7 模型对比与统计接口（FR-05）

- `GET /models`、`/models/{name}/curves`、`/models/{name}/confusion`、`/stats/overview`（总数、Top-1 置信度分布、近 7 天趋势、识别 Top-10 类别）
- 判据：曲线与混淆矩阵数据可被前端渲染；`/healthz` 返回 `gpu_available` 与 `model_loaded`

### M3-8 后端自测

- 写 `backend/tests/`（pytest + `TestClient`）：认证 3 例、识别 4 例（成功/类型错/超大/损坏）、权限 2 例、百科 2 例
- 判据：`pytest -q` 全绿（覆盖率不求高，但关键路径必须覆盖）

**M3 完成标志**：`/docs` 上全部接口手动自测通过，pytest 通过，识别结果与离线评估一致。

## 8. 执行纪律（怎么做才不返工）

1. **一个里程碑一个可运行状态**：M1 结束能冒烟训练，M2 结束能出指标，M3 结束能用 `/docs` 演示，M4 结束能全流程点击。任何阶段都不留"半成品等以后再补"。
2. **接口先行**：M3、M4 都严格按文档 02 §4 的契约实现，字段名以契约为准，改动需同步更新文档。
3. **训练与推理一致性**：预处理函数只有一份实现，训练与后端共用，避免"报告 96%、线上 70%"。
4. **每完成一个里程碑即 commit 一次**，commit message 写清里程碑编号。
5. **不做范围蔓延**：文档 01 §5.3 的可选加分项只在主线全部完成后才动。
6. **失败就记录**：调优失败的轮次也要写进报告（消融实验），不要删除。
