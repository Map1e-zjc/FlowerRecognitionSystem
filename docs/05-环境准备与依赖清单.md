### 7.1 ⚠️ 脚本编码陷阱（已踩，务必遵守）
本机默认 Shell 是 **Windows PowerShell 5.1**，它读取 `.ps1` **不带 BOM 的 UTF-8 文件时按 ANSI(GBK) 解码**，
中文注释/字符串会被解成乱码，多字节序列还会破坏引号配对，报出误导性的
`The string is missing the terminator: "` 语法错误（实测 `download_data.ps1`、`train_all.ps1` 均中招）。

**规则**：

1. 任何含中文的 `.ps1` **必须存为 UTF-8 with BOM**（前三字节 `EF BB BF`）。
2. 由于用 `write` 工具生成的文件默认无 BOM，写完 `.ps1` 后必须补 BOM：

   ```powershell
   $enc  = New-Object System.Text.UTF8Encoding($true)   # $true = 带 BOM
   $text = [System.IO.File]::ReadAllText($p, [System.Text.UTF8Encoding]::new($false))
   [System.IO.File]::WriteAllText($p, $text, $enc)
   ```
3. 写完必须做语法自检（不需要执行脚本）：

   ```powershell
   $e = $null; [System.Management.Automation.Language.Parser]::ParseFile($p, [ref]$null, [ref]$e) | Out-Null
   if ($e) { $e[0].Message; $e[0].Extent.StartLineNumber }
   ```
4. 只用 PowerShell 5.1 兼容语法：**不要用** `??`、三元 `? :`、`&&`/`||` 管道链（这些是 7.x 才有）。
5. Python 侧同理：脚本输出中文前设置 `$env:PYTHONIOENCODING='utf-8'`、`$env:PYTHONUTF8='1'`，
   否则中文日志在 5.1 控制台会乱码。
6. 读取由 Python 写入的 UTF-8 日志必须显式指定编码：`Get-Content x.log -Encoding UTF8`，
   否则 PowerShell 5.1 会按 GBK 解码，中文日志显示为乱码（文件本身没坏，只是显示错）。

### 7.2 ⚠️ 缓存目录与日志输出治理（已踩，已加固）

**陷阱 A：不设 `TORCH_HOME` 会写 C 盘并失败**

torchvision / timm 的预训练权重默认下载到 `C:\Users\<user>\.cache\{torch,huggingface}`。
本机 C 盘余量仅约 15 GB；在受限环境下写该路径会直接报
`PermissionError: [WinError 5] 拒绝访问: 'C:\\Users\\11879/.cache\\torch'`，
报错完全指不到真正原因。

→ 加固：`ml/utils.py::ensure_cache_env()` 已在 `ml/train.py`、`ml/evaluate.py` 入口处兜底设置
`PIP_CACHE_DIR / TORCH_HOME / HF_HOME / HF_ENDPOINT` 到项目内 `.cache/` 并自动建目录，
**显式传入的环境变量优先级更高**。因此直接 `python -m ml.train ...` 也是安全的。

**陷阱 B：tqdm 在非 TTY 下刷屏**

tqdm 在后台作业 / 管道 / 日志采集（`stderr` 非终端）下依然逐步输出。
实测 ConvNeXt-Tiny 只跑 40 秒就产生 **157.8 KB** 控制台日志，60 epoch 推算可达 10 MB 级，
会打爆作业输出缓冲区并淹没关键信息。

→ 加固：进度条收敛到唯一实现 `ml/utils.py::make_bar`，默认 `auto` 策略 ——
仅当 `stderr.isatty()` 为真才显示。控制方式：

```powershell
python -m ml.train --config ... --no-progress     # 后台作业推荐
python -m ml.train --config ... --progress        # 本地终端想看进度条时
$env:ML_PROGRESS = '0'                            # 等价的环境变量开关
```

**实测对照**（同一 3-batch 单 epoch）：默认 **3.61 KB** vs `--progress` **18.97 KB**。
后台运行的可靠进度来源是 `ml/outputs/logs/<tag>_train.csv`（逐 epoch 一行）。
