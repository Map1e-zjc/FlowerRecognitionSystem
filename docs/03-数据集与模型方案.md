# 03 · 数据集与模型方案

## 1. 数据集：Oxford 102 Category Flower Dataset

| 项 | 内容 |
| --- | --- |
| 全称 | Oxford 102 Category Flower Dataset (Flowers-102) |
| 规模 | 8189 张图片，102 个类别 |
| 图片来源 | 英国常见花卉，每类 40—258 张不等 |
| 官方划分 | train **1020**（10/类）· val **1020**（10/类）· test **6149** |
| 标注文件 | 官方为 `imagelabels.mat`（1-based 标签 1—102）、`setid.mat`（trnid/valid/testid） |
| 磁盘占用 | 官方 tgz 约 330 MB；**本机实际使用的 HF 镜像封装约 3.2 GB**（见下） |
| **本项目实际来源** | `hf-mirror.com` 的 `dpdl-benchmark/oxford_flowers102`（parquet 封装，ADR-011） |
| 为什么换源 | 官方 `www.robots.ox.ac.uk` 在本机**无法解析**（DNS SERVFAIL），公共 DNS 查询亦超时 |
| 数据一致性 | HF 镜像的三个划分规模（1020 / 1020 / 6149）与 102 类标签**与官方完全一致**，结论仍与论文可比 |
| 清单文件 | 转换后生成 `data/flowers-102/manifest.json`，是划分与 0-based 标签的唯一权威来源（ADR-013） |
| 读取方式 | `python -m ml.download_data --root data --source hf` → `ml.dataset.load_manifest()` |
| 备选源 | `--source oxford`（官方 tgz，需网络可达 ox.ac.uk）；Kaggle 镜像需 `kaggle.json` |
| 类别名 | 社区通用 `cat_to_name` 表（1-based 顺序），已内置为 `ml/dataset.py::CLASS_NAMES_EN`（102 项，已校验无重复） |
| 许可 | 仅限学术研究使用，报告中需注明出处与引用 |

### 1.1 关键特点与影响

1. **训练集极小（10 张/类）** → 必须使用 ImageNet 预训练 + 迁移学习，禁止从零训练；需强数据增强与较强正则。
2. **官方 test 分布不均衡（40—258/类）** → 报告中除 Top-1/Top-5 外，补充**宏平均（macro-F1）**，避免被大类主导。
3. **细粒度分类** → 类间差异小（如玫瑰 vs 月季、不同品种水仙），错误分析必须做，混淆矩阵是核心可视化。
4. **无官方中文名** → 需人工整理 102 条中英对照 + 百科字段（`flowers.json`），预估 3—5 小时，安排与 M2 训练并行。

### 1.2 划分策略（两个评估协议，报告中都给）

| 协议 | 训练集 | 验证集 | 测试集 | 用途 |
| --- | --- | --- | --- | --- |
| **P1 官方协议（主）** | 1020 | 1020 | 6149 | 主结果，与论文可比 |
| **P2 增强协议（对比）** | 1020 + 1020 = 2040 | 从训练集 5 折交叉验证 | 6149 | 说明"更多数据能提升多少"，作为消融实验 |

- P1：用 val 选最优 epoch 与超参，最终在 test 上报告一次。
- P2：仅在时间充裕时做，作为加分消融项（不作为主线阻塞）。

## 2. 模型候选与预期指标

评估环境：RTX 4060 Laptop 8 GB；输入 224×224；AMP 混合精度。

| 模型 | 来源（timm 解析出的 hub 仓库） | 参数量 | 预期 Top-1 | 预期 Top-5 | batch | 预计耗时 | 定位 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| **ResNet-50** | torchvision `IMAGENET1K_V2` | **23.72 M**（实测，含 102 类头） | 93—95% | ≥ 99% | 32 | 约 45 min（60 ep） | 基线 baseline |
| **EfficientNet-B0** | timm `tf_efficientnet_b0` → `timm/tf_efficientnet_b0.ns_jft_in1k` | **4.1 M**（实测） | 94—96% | ≥ 99% | 32 | 约 40 min（60 ep） | 轻量高性价比 |
| **ConvNeXt-Tiny** | timm `timm/convnext_tiny.fb_in22k_ft_in1k` | **27.9 M**（实测） | 95—97% | ≥ 99% | 24 | 约 70 min（60 ep） | 现代 CNN |
| **ViT-B/16** | timm `timm/vit_base_patch16_224.augreg_in21k_ft_in1k` | **85.9 M**（实测） | 96—98% | ≥ 99.5% | 16（+累积 2） | 约 60 min（40 ep） | 冲最优指标 |

> 参数量已按 M1 实测回填（与论文数字的差异来自「是否含 1000 类原分类头」）。
> 耗时为**基于 M1 冒烟实测的推算值**：ResNet-50 单 epoch ≈ 25 s 训练 + 18 s 验证 ≈ 45 s，
> 瓶颈在数据加载（`num_workers=0`，GPU 利用率仅约 18%），60 epoch 约 45 分钟。
> 精度目标（ADR-001 总体目标）：**最优模型 Top-1 ≥ 95%、Top-5 ≥ 99%**。
> 若 ViT 显存不足，降级顺序：ViT-B/16 → ConvNeXt-Tiny → EfficientNet-B0。

### 2.1 8 GB 显存预算与应对

| 模型 | 224px batch | 峰值显存 | 说明 |
| --- | --- | --- | --- |
| ResNet-50 | 32 | **1727 MB（M1 实测）** | 余量远超预期（预算 3.5 GB） |
| EfficientNet-B0 | 32 | ~1.5 GB（推算） | — |
| ConvNeXt-Tiny | 24 | ~4.5 GB（推算） | 超限则降到 16 |
| ViT-B/16 | 16 | ~6.5 GB（推算） | 梯度累积 ×2 保持等效 batch 32；必要时 192px 微调 |

> ResNet-50 实测仅 1727 MB / 8188 MB，说明 8 GB 显存比预算宽裕得多 ——
> ViT-B/16 用 batch 16 甚至 24 都有较大把握，M2-5 会实测后回填。

统一启用：`torch.amp.autocast('cuda')` + `GradScaler`；`torch.backends.cudnn.benchmark = True`；训练前 `torch.cuda.empty_cache()`。

## 3. 训练方案

### 3.1 分类头与微调策略

- 主干：ImageNet 预训练权重；`num_classes = 102` 替换原分类头。
- 分层学习率：主干 `lr_backbone = 3e-5 ~ 1e-4`，新分类头 `lr_head = 1e-3`（`param_groups` 实现）。
- 前 3 个 epoch **冻结主干**只训分类头（warmup，稳定初期梯度），之后解冻全网络微调。

### 3.2 统一超参（各模型 config 里可覆盖）

| 项 | 值 |
| --- | --- |
| 输入尺寸 | 224×224（ViT 若显存紧张可 192） |
| 优化器 | AdamW，`weight_decay = 0.05` |
| 学习率调度 | CosineAnnealingLR，`T_max = epochs`，`eta_min = 1e-6`，前 3 epoch 线性 warmup |
| epoch | 60（ViT 可 40，因收敛更快） |
| batch size | 见上表 |
| 损失函数 | CrossEntropyLoss + `label_smoothing = 0.1` |
| 梯度裁剪 | `clip_grad_norm_ = 1.0` |
| 早停 | val Top-1 连续 10 epoch 不提升则停止，保存最佳权重 |
| 随机种子 | 42（`random` / `numpy` / `torch` / `cuda` 全部固定，NFR-06） |

### 3.3 数据增强

**训练集**

1. `RandomResizedCrop(224, scale=(0.6, 1.0), ratio=(0.75, 1.33))`
2. `RandomHorizontalFlip(p=0.5)`
3. `ColorJitter(brightness=0.3, contrast=0.3, saturation=0.3, hue=0.05)`
4. `RandomRotation(degrees=15)`
5. `RandAugment(num_ops=2, magnitude=9)`（可选，若过拟合则启用）
6. `RandomErasing(p=0.25)`（可选）
7. `ToTensor` + `Normalize(mean=[0.485,0.456,0.406], std=[0.229,0.224,0.225])`

**验证 / 测试集**：`Resize(256)` → `CenterCrop(224)` → `ToTensor` → `Normalize`（同上）。

> **推理一致性铁律**：后端 `services/inference.py` 的预处理必须与评估脚本**完全一致**（同尺寸、同归一化参数、同插值方式），否则线上精度会明显低于报告值。实现时把预处理抽成一个公共函数，训练与推理共用。

## 4. 评估协议与产出

### 4.1 评估指标

| 指标 | 说明 |
| --- | --- |
| Top-1 / Top-5 Accuracy | 主指标（test 6149） |
| Macro-F1 / Weighted-F1 | 应对类别不均衡（sklearn 计算） |
| 每类准确率 | Top-10 最差类别列表，用于错误分析 |
| 混淆矩阵 | 102×102，导出 PNG 热力图 + JSON 数据 |
| 参数量 / 单张推理耗时 | 前向 100 次取均值（预热 10 次后计时） |
| 训练耗时 | 墙钟时间，写入 `metrics.json` |

### 4.2 必须产出的文件

```
ml/outputs/
├─ checkpoints/{model}_best.pth        # 最优权重（按 val Top-1）
├─ logs/{model}_train.log              # 逐 epoch 日志
├─ figures/{model}_curves.png          # loss / acc 双曲线
├─ figures/{model}_confusion.png       # 混淆矩阵热力图
├─ figures/compare_models.png          # 4 模型指标对比柱状图
├─ figures/error_cases/                # Top-20 高置信度错分样本拼图
```

### 4.3 错误分析要求（报告加分点）

1. 统计混淆矩阵中**互为 top 混淆对**的前 10 组（如 xx vs yy），逐组给出原因假设（花色相近 / 拍摄角度 / 背景干扰）。
2. 给出 3—5 张高置信度错分样本的图片与分析。
3. 给出后续改进方向：更强增强、更大输入分辨率（384）、度量学习（ArcFace）、两阶段（先分科属再分类）。

## 5. 花卉百科数据（FR-02）构建方式

1. 从数据集 `imagelabels.mat` 得到 102 个类别及其英文名（名称表可由 `torchvision.datasets.Flowers102` 的类别元数据或官方 `cat_to_name.json` 提供）。
2. 用脚本生成 `flowers.json` 骨架：`{id, name_en, name_cn:"", family:"", ...}`，102 条全部占位。
3. 人工补全中文字段（这是**唯一无法自动化**的部分，预估 3—5 小时），策略：
   - 优先补全 Top-30 常见花卉（玫瑰、郁金香、向日葵、水仙、鸢尾等），保证演示效果；
   - 其余字段允许先留空，前端对空字段做"暂无资料"降级展示，不阻塞 M4。
4. 校验脚本：断言 102 条、id 连续 0—101、`name_cn` 非空条数 ≥ 60。
