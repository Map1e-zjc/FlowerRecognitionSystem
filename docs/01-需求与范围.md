# 01 · 需求与范围

## 1. 项目背景与目标

传统花卉识别依赖人工比对植物图鉴，普通用户难以准确判定种类。本项目构建一个基于深度迁移学习的 **AI 花卉识别系统**，用户上传一张花卉照片即可获得 Top-5 候选种类、置信度以及该花卉的百科与养护信息，同时系统保留识别历史并展示不同模型的性能对比。

**总体目标**

1. 在 Oxford Flowers-102 上完成 3 个主干网络的迁移学习对比，最优模型 **Top-1 ≥ 95%、Top-5 ≥ 99%**。
2. 交付一个可现场演示的 Web 系统：登录 → 上传图片 → Top-5 结果 → 查看百科 → 历史记录。
3. 产出可复现的训练脚本、模型指标文件与实验报告。

## 2. 用户角色

| 角色 | 说明 | 主要诉求 |
| --- | --- | --- |
| 游客（未登录） | 未注册访问者 | 浏览花卉百科列表与详情、查看模型对比页 |
| 普通用户（已登录） | 唯一注册角色（ADR-007） | 上传图片识别、查看/删除自己的识别历史、查看统计概览 |
| 演示者（答辩人） | 即普通用户 + 管理员权限外的操作 | 一键启动系统、展示模型对比与混淆矩阵 |

> 系统**不设**管理员角色，不提供用户管理后台（ADR-007）。

## 3. 功能需求（FR）

### FR-01 图片上传识别（核心）

- 支持格式：JPG / JPEG / PNG / WEBP；单文件 ≤ 5 MB；读取时自动按 EXIF 纠正方向。
- 输入：一张图片 + 可选模型选择（默认最优模型）。
- 输出：Top-5 列表，每项含**类别 ID、英文名、中文名、置信度**；另返回**推理耗时(ms)**、使用模型名、记录 ID。
- 失败处理：非图片文件、文件过大、损坏图片、模型未加载 → 返回结构化错误码与中文提示。
- 前端需展示 Top-5 置信度条形图（ECharts）。

### FR-02 花卉百科 / 养护知识库

- 提供 102 类花卉的结构化资料：中文名、英文名、科、属、花期、花色、光照、浇水、土壤、繁殖方式、简介、代表图。
- 列表页支持按中文名/英文名搜索、分页；详情页支持从识别结果一键跳转。
- 数据来源：类别名来自数据集，其余字段由项目内 `flowers.json` 人工整理（102 条，预估 3—5 小时，可与 M2 训练并行）。

### FR-03 识别历史记录

- 登录用户可查看自己的识别记录：缩略图、识别结果、置信度、模型、时间。
- 支持分页、按花卉种类筛选、按时间倒序；支持删除单条记录。
- 记录与用户强绑定，用户之间数据隔离（越权访问返回 403/404）。

### FR-04 用户注册与登录

- 注册：用户名（唯一，3—20 字符）、邮箱（唯一，格式校验）、密码（≥ 8 位，需含字母与数字）。
- 密码使用 bcrypt 哈希存储，**数据库不存明文**。
- 登录成功返回 JWT（有效期 12 小时），前端存 localStorage，请求头携带 `Authorization: Bearer <token>`。
- 未登录用户可浏览百科与模型对比页；识别与历史功能需登录（未登录点击时跳转登录页）。

### FR-05 模型对比与可视化

- 展示各模型（ResNet-50 / EfficientNet-B0 / ConvNeXt-Tiny / ViT-B/16）的：Top-1、Top-5、参数量、单张推理耗时、训练耗时。
- 展示训练曲线（loss / accuracy）与 **102×102 混淆矩阵热力图**。
- 展示典型错分案例（如"玫瑰 vs 月季"）图片对比，作为错误分析。
- 数据来源：训练阶段导出的 `ml/outputs/metrics.json` 与 `figures/*.png`，由后端读取后经 API 提供给前端（不在前端硬编码）。

### FR-06 训练脚本与实验报告

- 一条命令完成指定模型的训练 + 验证 + 测试 + 指标导出。
- 导出内容：最优权重 `.pth`、`metrics.json`、训练曲线图、混淆矩阵图、`--help` 可用的参数说明。
- 实验报告（Markdown/Word）：任务背景、数据集、方法、超参、对比结果表、可视化、错误分析、结论与改进方向。

## 4. 非功能需求（NFR）

| 编号 | 需求 | 指标 |
| --- | --- | --- |
| NFR-01 | 推理性能 | GPU 下单张端到端（含网络）< 1.5 s；纯推理 < 300 ms |
| NFR-02 | 页面性能 | 首个页面可交互 < 2 s（本机 localhost） |
| NFR-03 | 并发 | 支持 ≥ 5 并发识别请求不崩溃（单 worker + 模型单例，队列化） |
| NFR-04 | 可用性 | 模型加载失败时服务仍可启动，识别接口返回明确错误而非 500 堆栈 |
| NFR-05 | 安全 | 密码哈希、JWT 校验、上传文件类型与大小白名单、文件名 UUID 化（防路径穿越） |
| NFR-06 | 可复现性 | 训练脚本固定随机种子；README 记录环境版本与完整命令 |
| NFR-07 | 可维护性 | 后端分层（api / core / models / schemas / services），前端组件化，配置外置到 `.env` |
| NFR-08 | 中文支持 | 全部界面文案与错误提示为中文 |

## 5. 范围边界

### 5.1 范围内（本期必做）

图片上传识别、Top-5 展示、花卉百科、识别历史、注册登录、模型对比可视化、训练脚本、实验报告、一键启动脚本。

### 5.2 明确不做（Out of Scope）

| 项 | 原因 |
| --- | --- |
| 移动端 App | 打包与适配成本高（ADR-001） |
| Docker 容器化 | Windows GPU 透传配置耗时（ADR-008） |
| 管理员后台 / RBAC | 单角色体系已定（ADR-007） |
| 摄像头实时视频流识别 | 答辩环境稳定性风险 |
| 多语言（i18n） | 时间成本，本期仅中文 |
| 在线增量学习 / 用户反馈再训练 | 工程量远超 2—4 周窗口 |
| 公网部署与域名/HTTPS | 仅本机演示（ADR-005） |

### 5.3 可选加分项（时间充裕才做）

1. 浏览器调用摄像头拍照识别（`getUserMedia`）。
2. Grad-CAM 热力图叠加，解释模型"看哪里"。
3. 自采本地花卉照片做零样本泛化测试。
4. Docker Compose 一键部署。
